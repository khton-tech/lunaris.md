# Application UI polish — 2026-11-13

## Result and evidence boundary

The source and interaction review produced corrections to shared layout, menus,
control states, typography, form cancellation, tab navigation and supporting tools.
Implementation lives on `fix/ui-polish`, based on `2d79374`; it is not merged.

The review covers all 24 registered Mantine roles, their product consumers,
document styling and host viewport ownership. The automated source guardrail scans
29 non-retired UI plugins and 114 source files. That scan is deliberately narrow;
it is not evidence that every possible visual or accessibility defect is absent.

Native visual acceptance remains pending. Repository instructions prohibit
automated desktop control. No browser/desktop automation was used, and no native
screenshots or real-device recordings were available for this pass. DOM tests
establish behavior, ownership and CSS declarations, not final rendering, geometry,
contrast or perceived motion.

References are the current Files and Settings navigation, Workspace tabs, mobile
dock and Vault selector, together with [UI guidelines](../UI_GUIDELINES.md).
[Mantine UI navigation](https://ui.mantine.dev/category/navbars/),
[Menu](https://mantine.dev/core/menu/) and
[Tooltip](https://mantine.dev/core/tooltip/) informed the review. Installed
Mantine 9.7.5 source and types were used to check implementation compatibility.

## Corrected findings

| Finding | Implemented result |
| --- | --- |
| Generic button hover could replace a filled action's accent while retaining accent text contrast | Filled hover/press keeps the semantic accent palette; optional Luna control finishes still apply |
| Hover could obscure persistent navigation selection; icon feedback was inconsistent | Selected Settings/rail/mobile rows retain selection; action icons use short themed feedback and reduced-motion rules |
| Textarea/password focus and invalid-field feedback were incomplete | Shared editable controls use the themed boundary; invalid borders survive hover; title focus uses one underline |
| Settings descriptions/errors lived outside Mantine wrappers and lost their input ARIA relationships | Text, number, switch and combobox controls retain external descriptions/errors through public Mantine attributes; sliders keep their existing relationship |
| Secondary text and status metrics bypassed theme size; Explorer extension text was too small | Shared secondary sizes follow the theme; footer metrics wrap and headings scale; phone extension labels retain their minimum size |
| Selected Settings values and recent Vault details could clip at narrow allocations | Select labels wrap; recent/account card rows adapt to their own column width; full account/Vault names appear in action menus |
| Dropdowns inside scrolling/contained regions risked clipping | Account, Files, Vault switcher, Settings, Backlinks, Lime and declarative choices use an SDK-mount-owned themed viewport overlay |
| Portaled menus could outlive the active region or become interactive during closing | Menus dismiss with hidden/inert owners and busy triggers; closing menus become inert immediately; overlays and observers are disposed with the role |
| Earlier theme exceptions removed supporting cards and framed the main workspace | Workspace consistently owns supporting surfaces and outer spacing; main has no enclosing decorative border/shadow; compact drawer stays flush |
| Luna Files repainted its borrowed panel; the rail split short-height scrolling between groups | Embedded Files inherits its panel; the rail scrolls as one region, including trailing tools |
| Escape on the editor title could trigger rename through blur | Cancellation is guarded before blur; IME Enter stays with composition; late rename failure cannot reset a replacement document's title |
| Vault create/open forms lacked the account form's cancellation behavior | Escape closes the form, preserves its draft and restores the disclosure trigger, while busy/composing states are respected |
| Desktop tab reordering was pointer-only | Alt+ArrowLeft/Right uses the existing reorder callback, follows direction and preserves selection; busy state blocks it |
| Mobile navigation did not reflect the desktop tab operation's busy state | Active Screen publishes disabled state to all dock actions, choices and close controls; UIKit closes a disabled picker and recovers without reopening it |
| Backlinks controls differed from Files and had incomplete collapse/filter focus behavior | Toolbar density and errors follow shared conventions; result text follows theme size; disclosures identify contents and restore focus; Escape closes the filter without clearing its query |
| Disclosure chevrons changed abruptly across shared controls | Vault rows, Backlinks and callouts use short theme transitions with reduced-motion support |

The overlay is internal composition inside mantine-components, not a new SDK
service. No new plugin, provider or private DOM integration was necessary. Settings
Items now defaults `portalDropdowns` to true; explicit false remains available to
hosts deliberately managing inline menus. The virtual File Explorer row model is
preserved rather than changing its measured height for long names.

## Integration assessment

Implementation is connected through existing public contracts:

- Workspace, Sidebar and Files receive shared region/navigation changes through
  their existing Components roles. Composed tests mount Files and the rail inside
  the actual Workspace layout role and verify transparent embedded roots.
- Settings/interface-settings, Lime, declarative views, Account Access and
  Backlinks receive themed menus through their existing roles. Tests exercise
  opened menus, selection, theme replacement, inactive targets, nested modal
  Escape, explicit inline opt-out and cleanup.
- Text Editor receives cancellation/error fixes through its existing rename
  callback. Its integration tests cover title identity, save/rename and Backlinks
  sorting in the editor footer.
- Active Screen uses existing MobileMenu disabled/choice/reorder contracts for
  compact navigation, and the existing tab callback for desktop keyboard ordering.
  The MobileMenu provider continues to reject stale or disabled invocations.
- Backlinks and Callouts keep document operations in their existing consumers.
  The shared role changes only controls, disclosure state and presentation.

No required SDK integration is outstanding. Native composed-view acceptance is
outstanding and must not be inferred from successful mounts or behavior tests.
Existing Logger requirements and lifecycle diagnostics remain in place.

## Manual acceptance requested

Use the actual Web/Tauri app and a supported phone/WebView. Check the composed
screen, including its owning container and an opened control, not an isolated
component. At minimum:

1. Open Files, Settings and the editor at desktop width, 360–390px width and short
   landscape height. Resize the side panel, add enough rail tools to overflow and
   verify the last item remains reachable. Check supporting cards and the open main
   region in Monochrome, Everforest and both Luna presets.
2. Open Settings language/theme/provider options, Files sorting, Vault switching,
   account actions and context submenus near each edge in a short window. Navigate
   to the last item, close with Escape, switch tools and change theme while open.
   Check focus, selected/hover/pressed/disabled states and dropdown containment.
3. Increase theme text size and use long Russian labels, paths and similar file
   names. Check Settings, recent Vaults, account details, tabs and footer metrics.
   Confirm that editable fields show one focus boundary and readable errors.
4. Rename a document, cancel with Escape, submit with Enter and an IME, and provoke
   a rename error. Expand/collapse Vault forms with retained drafts. Test Backlinks
   filtering, group collapse and editor-footer results. Reorder desktop tabs with
   Alt+ArrowLeft/Right and check close/history focus.
5. On touch, open more than five tabs, reorder/scroll the picker, close a tab and
   perform a document transition that waits for saving. Confirm busy dock actions
   cannot be used and recover in place. Test the drawer and edit the last document
   line with the virtual keyboard open, then close it and switch tools.
6. Repeat disclosure and drawer transitions with reduced motion, including rapid
   open/close. Check callout/task controls, loading/empty/error/recovery states and
   Lime preview/provider selection inside the actual modal.

Record device/browser, theme, viewport and the failing screen. Popup placement
needs a complete screenshot; motion and keyboard overlap need a short recording
or an explicit behavior report. This acceptance remains pending until observed.
